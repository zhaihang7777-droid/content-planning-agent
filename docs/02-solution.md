# 方案

Python标准库原生实现，避免额外框架安装；SQLite保存请求结果与活动方案。agent.py 管理执行循环和约束，state.py 提供步骤状态，tools.py 提供合成业务工具，deepseek_model.py 调用真实模型，CLI读取JSON请求。

流程为输入校验、请求去重、模型选择动作、应用校验参数和预算/时间、执行工具、记录观察、再次请求模型。预设步骤骨架是检索、估算、生成、保存；实际执行顺序和替代选择由模型根据观察决定。模型上下文包含费用表、已发生费用、剩余时间和工具历史。最多12次工具调用，达到上限返回未完成。

模型输出JSON动作及简要依据，不要求或存储内部思维过程。生成前需有成功检索，保存前需匹配成功生成内容；实际保存时由应用补齐主题、目标、素材来源、费用及步骤结果。只有成功保存证据才能支持completed。预算逐次拦截，估算计入已发生费用；模拟耗时与实际等待均用于默认时钟下的截止时间检查。

相同请求ID与相同输入复用结果；输入改变返回冲突。失败后显式恢复，匹配动作参数复用成功结果并保留费用。事务覆盖本地运行，异常和中断回滚。长模型调用持有SQLite写锁，适合本地评审，不适合并发服务。

已验收主路径为DeepSeek。素材检索使用子串匹配，脚本生成是本地合成工具，standard与economy仅模拟不同费用和耗时，不声称真实质量差异。模型/API token实际费用不属于模拟业务预算。无真实发布、付款或视频生成。
