# 需求与验收

## 目标与范围

用户为内容运营人员。输入主题、预算和截止时间，Agent 检索合成素材、生成脚本、核算费用和耗时并保存内容活动方案。以 CLI 作为首版运行入口（工程设计选择）。不接真实发布、付款或视频生产。

## 输入约定（工程设计选择）

- request_id：同一逻辑请求的唯一标识，用于防重复。相同 ID 但内容改变应拒绝并说明冲突。
- theme：非空活动主题。
- budget：非负整数，单位为模拟费用单位。
- deadline：带时区的 ISO 8601 时间。
- started_at：实际启动时间；测试可注入固定时间，以便复现截止时间判断。

缺少预算或截止时间必须返回 needs_input，指出字段；不得自行补值。非法输入同样明确报告。所有费用、素材和耗时均为合成数据。

## 输出约定

输出请求 ID、任务状态、计划及依赖、每步状态与工具结果、方案费用合计、已发生费用、预计剩余耗时、保存方案 ID 或未完成原因、资料缺口以及 Trace。

任务状态：completed、needs_input、incomplete、failed。步骤状态：pending、running、succeeded、failed、skipped。只有所有必需步骤成功、满足预算和时间约束且保存工具确认成功，才可 completed。

费用表中的执行操作在成功时计费；失败是否计费由工具结果明确给出。方案预估费用与已发生费用分别展示；改用替代方案时需计入不可退回的已发生费用，不得漏算或重复计算。时间核算基于串行执行假设，计入实际已耗时间与预计剩余时间。截止时间不能只展示而不检查。

## Agent 决策要求

模型选择动作，执行工具，观察返回结果，再选择调整计划、替代方案、重试、追问或结束。固定条件分支和自动重试不能替代真实模型决策。工具负责计算与执行，应用层负责约束校验；不得仅相信模型声称成功。

至少两条真实模型执行路径体现工具结果导致动作变化。Trace 记录步骤、工具参数、结果摘要、下一动作及简要依据，不保存内部思维过程。首版工具调用上限拟设为 12 次，达到上限返回 incomplete 并保留已完成结果。

## 必须验收

1. 正常完成：费用和时间满足约束，方案保存成功。
2. 缺预算或截止时间：明确请求补充，不虚构约束。
3. 工具失败：不将失败标记为成功；模型决定调整或停止。
4. 超预算：观察初始方案估算后换用可行替代方案，再估算和保存；无可行方案时说明缺口。
5. 重复执行：相同请求复用已保存结果，不重复生成、计费或保存；变更内容不能被错误复用。

失败步骤续跑为加分项：保留成功结果，恢复后仅执行未完成步骤，重新检查预算与时间。

补充工程验收：截止时间不足、保存失败、步数达到上限均返回真实未完成状态。

## 交付约束

同一仓库包含 README、src、tests、examples、data、5 份要求文档、依赖与 .env.example。至少 3 组输入、实际输出和记录覆盖全部验收点；案例设计不能冒充运行结果。真实模型不可用时提供离线 Mock 并明确其边界。记录 AI 辅助、个人修改验证、实际用时与未完成项。不提交密钥或隐私数据。最终提交题号 2、GitHub URL 与 commit SHA。
